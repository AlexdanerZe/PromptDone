# PromptDone 极简 MVP 页面结构原型

- **状态**：供用户选择信息架构，尚未定稿。
- **决策议题**：[确认极简 MVP 页面结构与关键交互草图](https://github.com/AlexdanerZe/PromptDone/issues/66)。
- **原型文件**：[单文件交互原型](minimal-mvp-ui-prototype.html)。
- **运行方式**：双击 HTML；通过顶部按钮或底部切换条选择 A/B/C。也可在文件 URL 中添加 ?variant=A、?variant=B、?variant=C。默认 B。

## 一、背景与本次问题

数据、工作流、评分/导出与四服务技术边界已收口。本原型只回答：怎样组织数据准备、修改 Prompt、固定数据跑测、标注和对比页面，才能减少切换和重复配置。

这是可丢弃原型，使用 8 条虚构商品记录、示例模型别名、示例 Prompt 和固定响应。运行进度、费用和翻译均为内置演示；没有调用 LiteLLM、解析真实上传文件或写入数据库。状态只在内存中，刷新重置，下载只生成示例文件。它不能证明产品功能或容量已实现。

## 二、三个候选方案

### A：资产导航

左侧入口为数据集、工作台、版本对比；工作台内选择任务再进入详情。模型与访问从设置进入。

数据和任务边界清楚，适合频繁跨任务复用数据的人；导入、运行和比较跨多个入口。没有增加独立 Prompt、Eval Suite 或术语库管理页面。

### B：任务聚合（建议 P01）

两张主要业务页：任务列表、任务详情。详情内有“数据／调优／对比”三个 Tab，模型和访问使用设置弹窗。共享口令入口是通用访问门，不计为业务管理页。

用户先进入要调优的任务，再在任务内准备和验证。数据版本、Node、当前运行与比较基准处于同一任务上下文。推荐 B，因为首版主要任务是反复调优一个工作流。

### C：数据表优先

数据表和运行结果占主区域，当前 Node 的 Prompt、模型及跑测控制位于右侧。顶部切换数据、运行结果与对比；任务列表用于切换上下文。

适合大量逐条检视数据；较窄窗口下需上下排列，Prompt 与对比内容更容易占据较多空间。

### 术语映射

“调优任务”对应 Workflow，“节点”对应 Node，“运行”对应 Workflow Run，“逐条详情”对应 Execution Trace，不新增其他业务对象。

## 三、推荐方案 B 的页面与交互提案

以下布局尚待用户选择；已确认业务规则以各原决策票为准。示例中的条数、模型别名、Prompt、Token、费用、耗时不构成新的限制或目标。

### 3.1 页面：任务列表

#### 主体板块：任务目录

##### 任务列表与创建

每项展示名称、数据版本、Node 数量、最近运行状态。

**内容说明**

- 任务名称可进入详情；无运行时显示“尚未运行”，不生成质量分数。
- “新建任务”打开名称弹窗；正式版本创建空 Workflow 后引导选择或导入数据。
- 模型设置从右上角进入，不作为一级业务列表。

**交互样式**

- **选择任务：** 进入详情，保留其节点、草稿和历史。
- **创建任务：** 保存名称后进入数据 Tab；取消不创建任务。

**数据处理**

- **input：** 当前工作区 Workflow 及最近 Workflow Run 摘要。
- **process：** 关联数据版本、节点数和最近状态，无运行时指标留空。
- **output：** 目录；创建时产生 Workflow，详情按其标识加载。

### 3.2 页面：任务详情

#### 顶部板块：当前任务与 Tab

##### 任务上下文

顶部展示名称、当前数据版本和 Node 概况，提供返回列表、三个 Tab 和设置入口。

**内容说明**

- 数据版本和当前 Node 始终可辨，不因切换页面静默更换比较输入。
- 历史运行仍使用冻结数据版本，不随当前任务后续选择变化。

**交互样式**

- **切换 Tab：** 保留草稿及选择，本身不调用模型、不发布数据或 Prompt。
- **返回列表：** 保留已保存状态；最终规格需明确未保存编辑的离开行为。

**数据处理**

- **input：** Workflow、当前编辑态及其 Workflow Runs。
- **process：** 区分当前配置和选中历史快照。
- **output：** 顶部上下文和当前 Tab 内容。

#### 数据 Tab：版本预览与导入

##### 数据版本与导入弹窗

主体展示版本记录，右上角打开“选择文件 → 映射与预览 → 清洗确认”导入弹窗。

**内容说明**

- 已保存版本只读，展示稳定记录 ID、Input、可选 Expected Output。
- 导入处明确 ≤20 MB、记录数 <50,000；正式列表分页。
- 映射选择输入字段和标准答案，只对显式 JSON 列修复。
- 清洗同时展示原文、结果、失败原因及纳入/排除数量。
- 排除和导出失败记录在同一弹窗完成；保存新版本不覆盖旧版。

**交互样式**

- **调整映射：** 更新预览，确认保存前不发布。
- **排除并导出失败记录：** 保存可用记录，保留诊断。
- **保存新版本：** 切换当前数据选择，旧运行仍绑定原版。
- **取消导入：** 不发布新版本。

**数据处理**

- **input：** 上传文件、映射/JSON 列选择和已有版本。
- **process：** 校验容量、解析、显式修复、失败与排除；不执行数据代码、不猜测截断内容。
- **output：** 预览/清洗结果、失败导出；确认后新的 Dataset Version 与 Records。

#### 调优 Tab：节点编辑与执行结果

##### 当前 Node 的 Prompt

水平 Node 条位于顶部，左侧编辑当前 Node，右侧保留历史与结果。

**内容说明**

- 展示 Node 名称、草稿/版本状态，输入来自数据字段或前序输出。
- 配置模型别名、输出要求、Prompt、适用参数。
- 保存草稿、发布版本、版本历史分开；恢复版本复制到草稿，不覆写历史。

**交互样式**

- **选择 Node：** 展示其配置，不改变其他 Node。
- **保存草稿：** 更新后续跑测编辑内容，历史不变。
- **发布版本：** 生成不可变 Prompt Version，不随每次输入递增。

**数据处理**

- **input：** Node、Draft/Prompt Versions、模型别名、输入映射。
- **process：** 校验引用和输出要求，区分草稿与发布版本。
- **output：** 草稿或新版本；启动运行时冻结实际配置。

##### 跑测、历史与逐条详情

左下为范围/复用控制；右上历史，右下结果表及选中记录详情。

**内容说明**

- 单条、前 N 条、随机 N 条；沿用记录清单避免重新抽样。
- 选择基准运行、指定起跑 Node，满足数据/配置条件时复用成功上游。
- 显示进度和成功/失败/跳过/未完成，支持取消后续及另建批次重跑。
- 结果表有坏例筛选、记录选择、规则/匹配/人工结果和费用，未知与未调用分开。
- 详情展示输入、原始响应、错误和实际发送消息；在此标注好/坏/未评价及原因。
- 点译展示辅助中文，原文及检查结果不变，翻译费用单列。

**交互样式**

- **启动运行：** 冻结配置与记录清单。
- **选择历史：** 查看当时快照，不自动覆盖草稿。
- **人工标注：** 独立保存，不覆盖规则结果。
- **选择导出：** 打开上下文预览，无选择时禁用批量导出。

**数据处理**

- **input：** Dataset Version/记录、Node、基准 Run、执行详情。
- **process：** 校验选择和复用，后端限并发持久化、前端轮询；人工评价与翻译分开关联。
- **output：** 新 Workflow Run、Execution Traces、覆盖数量及人工标记；重跑不覆盖原批次。

#### 对比 Tab：同批输入两版对照

##### 配置、指标和逐条 Diff

顶部选择运行，中部配置/指标并排，下部逐条对照，退化置顶。

**内容说明**

- 使用同数据版本、同记录清单、同 Node，按记录 ID 对齐。
- 展示 Prompt/模型参数、分项指标与覆盖、耗时/Token/费用。
- 整体匹配率相同仍可能出现改善和退化，原型对此有示例。
- 分别呈现规则、答案、人工或执行退化，未评价不算坏评。
- 原始输出并排，支持报告与坏例导出；AI 总结/聚类、专用 Review 后置。

**交互样式**

- **切换运行：** 重新校验对齐条件，不符合时提示。
- **选择记录：** 展示相同记录 A/B 输出，选择坏例可导出。
- **导出报告：** 生成当时口径的汇总和明细，不改变运行。

**数据处理**

- **input：** 两个 Runs 的冻结配置、清单、规则结果、人工评价。
- **process：** 对齐、分项计算变化、确定性退化排序、标明未知。
- **output：** 配置/输出 Diff、指标、报告、外部 Harness 上下文。

### 3.3 通用弹窗与访问入口

#### 模型与访问设置

展示 LiteLLM 地址、密钥掩码、默认执行/辅助翻译别名和可选单价。厂商配置在网关管理，保存/取消分开，真实连通性待实现验证。

- **input：** 工作区网关配置、用户输入；响应不含明文密钥。
- **process：** 服务端校验、加密保存，缺单价不记成真实零。
- **output：** 更新之后可选配置，历史快照不变。

#### Context Bundle 预览

展示选中数量、字段和可复制文本，支持复制/下载 Markdown。复制受限时保留可选择文本，不误报成功。

- **input：** 选中记录及关联 Run、Prompt、人工标注。
- **process：** 仅允许的诊断字段，不包含系统凭证。
- **output：** 用户交给 Codex/Antigravity 的文本或文件，不自动发送。

#### 共享口令入口

最终规格补充最小访问表单：口令、进入按钮、错误反馈；通过后进入任务列表。口令由部署配置，业务页不管理个人账号。此通用入口未制作视觉变体。

## 四、已执行的原型检查

已通过 Orca 浏览器操作原型控件：

- 同批按 ID 对照，退化置顶；选择坏例后预览并下载 Markdown。
- 基准上游复用生成运行 C，沿用同批记录，A 的 Prompt 快照不变。
- 发布 v3 后在版本历史可见。
- 导入并排除一条错误记录后生成数据 v2，原 A/B/C 仍绑定 v1。
- A/B/C 切换改变结构和 URL。

这些检查仅验证原型状态和演示路径，不是后端、真实解析、容量或模型集成测试。

## 五、待用户审阅

选择 A、B、C，或指出希望组合的部分；推荐 B。反馈入口缺失或希望减少的切换即可。

ui-ux-pro-max 两次检索偏向官网/营销页，没有适用的信息架构匹配，因此未持久化检索输出。原型采用通用的数据表检视、明确状态、显式保存、键盘控件和主题变量，不把检索结果当成已验证业务设计。
