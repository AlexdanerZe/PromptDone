# PromptDone 统一工作台原型：页面结构修订

- 关联：[页面结构决策](https://github.com/AlexdanerZe/PromptDone/issues/66)。
- 来源：用户审阅上一版后明确要求多个数据集、多个任务、多运行历史、可添加步骤，并要求任务列表不要独立成页。
- 原型：[统一工作台](minimal-mvp-unified-workbench-prototype.html)；双击即可运行，无依赖。
- 边界：全部使用虚构记录和固定响应，状态仅在内存中；不会上传真实文件、调用模型或写数据库。数字、模型别名、响应、费用均为示例。

## 一、收敛后的信息架构

只保留一个业务工作台框架，顶部切换“工作台／数据集”，左侧任务目录始终存在。不存在独立任务列表页或“返回任务列表”跳转。

- 左侧：任务搜索、新建、多个任务、每个任务的数据绑定、步骤数与历史数量。
- 当前任务主体：任务名称、数据集/版本绑定，以及“调优／运行历史／版本对比”三个 Tab。
- 数据主体：多个具名数据集列表、各自的不可变版本、记录预览、新建数据集与新增版本。
- 通用弹窗：新建任务、选择数据集版本、添加步骤、Prompt 版本、导入向导、模型设置、Context Bundle。
- 共享口令为通用访问入口，技术与行为沿用已确认方案。

界面“调优任务”就是 Workflow，不新增另一层任务/会话容器。

## 二、页面 → 板块 → 模块

### 2.1 常驻左侧板块：任务目录

#### 多任务与任务内状态

**内容说明：** 每项展示任务名称、当前数据集版本、线性步骤数、运行历史数量和最近运行。空任务显示尚未运行，输入搜索只过滤目录。

**交互样式**

- **选择任务：** 原位更新主体，任务目录不消失；各任务保留自己的草稿、节点、选中运行和比较对象。
- **新建任务：** 输入名称后加入目录并选中，初始无历史；不跳到独立列表页。
- **切换到其他任务：** 不取消正在执行的运行；任务状态和结果仍按所属任务更新。

**数据处理**

- **input：** 工作区的 Workflows、各自当前数据绑定与最近 Workflow Runs。
- **process：** 所有编辑状态和历史查询按 workflow_id 隔离；列表过滤不改变当前任务数据。
- **output：** 常驻目录和当前任务上下文；新任务独立保存，不能共用另一任务的运行历史数组。

### 2.2 数据主体板块：数据集目录与版本预览

#### 多个 Dataset 与各自版本

**内容说明：** 列表展示名称、版本数量、最新记录数、当前绑定任务数；选中数据集后在同一主体内预览某个版本。

**交互样式**

- **新建数据集：** 指定名称并导入，创建独立 Dataset 的首个版本。
- **新增版本：** 在指定 Dataset 下重新导入，生成下一版本；不修改旧版。
- **用于当前任务：** 明确选择 Dataset Version，更新当前任务后续运行的数据绑定；不修改已存在运行或其他任务。
- **查看其他版本：** 只读预览，预览动作本身不更换任务绑定。

**数据处理**

- **input：** Datasets、Dataset Versions、Dataset Records 及当前任务绑定。
- **process：** 记录身份以版本和 record_id 关联；每个任务当前选择一份版本，不新增多数据集合并/join 能力。
- **output：** 数据集目录、版本预览或新的任务绑定；历史运行继续引用其冻结版本。

#### 导入弹窗

三步为选择示例文件/目标数据集、字段映射与显式 JSON 处理、清洗确认及失败排除。真实产品继续支持 .xlsx、CSV、JSON，单文件 ≤20 MB、记录数 <50,000。

- **input：** 上传文件、字段角色、显式 JSON 列及目标 Dataset（已有或新建）。
- **process：** 解析与清洗保留原文和错误；只处理显式 JSON 字段，不补造截断内容；发布前处理/排除失败记录。
- **output：** 新 Dataset 或新的不可变 Dataset Version；原运行不被重绑。

### 2.3 当前任务主体：步骤与调优

#### 动态线性步骤

**内容说明：** 水平步骤条可选择步骤，末尾有“添加步骤”。每步独立维护输入来源、Prompt 草稿/版本、模型和输出要求。

**交互样式**

- **添加步骤：** 输入名称后追加到末尾，生成稳定步骤标识，默认输入为前一步输出。
- **切换步骤：** 显示该步骤自己的编辑内容和对应历史结果，不把最终步骤结果复制给新步骤。
- **发布或恢复 Prompt：** 仅作用于当前步骤；恢复复制到草稿，历史版本与运行快照不变。

**数据处理**

- **input：** 当前 Workflow 的 Node 序列及各自 Prompt 配置。
- **process：** 追加只修改当前工作流草稿；启动运行时冻结完整节点序列和输入映射。
- **output：** 新 Node 或当前草稿更新；新运行包含新步骤，旧运行继续保持原来的节点数量与定义。

#### 跑测与记录详情

调优 Tab 左侧编辑当前步骤并选择单条/前 N/随机 N、基准运行和起跑步骤；右侧展示最近三次运行、当前历史快照的指标和记录详情。

- **input：** 当前 Dataset Version、实际选择的记录清单、Node 配置、可复用的基准输出。
- **process：** 保存快照、校验同数据与上游配置，满足条件才复用；后端限并发执行，页面轮询任务所属状态。
- **output：** 新 Workflow Run 及各记录/Node 的 Execution Traces；刷新/切任务不取消，失败/中断仍按已确认规则处理。

查看旧运行时，如果当前步骤不在旧快照里，显示“此运行不包含当前步骤”，不展示别的步骤结果。可选择查看历史的最后步骤，或执行新批次验证新步骤。

### 2.4 当前任务主体：多运行历史与对比

#### 运行历史表格

**内容说明：** 列为批次/时间、数据集版本、步骤/Prompt 版本、模型/条数、状态、设置 A/B。调优 Tab 提供最近运行摘要，运行历史 Tab 展示当前任务全部运行并筛选。

**交互样式**

- **选择历史批次：** 显示冻结结果，不覆盖当前草稿或重绑当前数据。
- **筛选历史：** 根据批次、数据、模型或状态查找；不查询其他任务的历史。
- **设置 A/B：** 直接选择两次运行后在任务内进入对比。

**数据处理**

- **input：** 当前 workflow_id 下的 Workflow Runs 及各自快照。
- **process：** 按时间倒序、分页/筛选，基于快照展示版本和模型；记录当前草稿与历史快照的区别。
- **output：** 可追溯历史、选中运行和对比对象，不新建任务列表页面。

#### 同节点对比

沿用已确认的同任务、同数据版本、同记录清单、同 Node 规则。新步骤若不在两个历史快照中，明确提示不能比较，允许选择共有步骤。

- **input：** A/B Run 快照、当前 Node、规则结果与独立人工标注。
- **process：** 按稳定记录 ID 对齐，分项计算规则/答案/人工变化，退化置顶；未知费用不记作真实零。
- **output：** 配置和输出 Diff、分项指标、Markdown 报告、CSV/JSON 明细与选中坏例上下文。

## 三、多历史展示的实际价值

- 看到每批到底用了哪份数据、哪些步骤和 Prompt、哪个模型，避免把“当前编辑内容”误当成历史配置。
- 同一任务内快速选 A/B，不必反复切任务或重新抽样。
- 新增第 3、4 步后，仍能追溯之前只有两步的批次。
- 多任务间历史不混合，切换上下文不丢草稿。

## 四、检查与边界

原型检查围绕任务隔离、多数据集绑定、新建任务、追加步骤、旧快照保留、新批次运行、历史筛选和对比导出。具体结果与截图随本文件一同归档。

这是页面信息架构与演示状态验证，不是生产实现、真实文件解析、数据库持久化、五万条容量或 LiteLLM 联调验收。
