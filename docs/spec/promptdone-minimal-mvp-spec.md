## 一、背景

项目开发需要用稳定的 Prompt 验证数据清洗和结构化处理，但原始 Excel、CSV、JSON 及偏 JSON 内容难以直接复用，多轮修改后的 Prompt、模型参数和输出也缺少统一记录。

本次建设内部 PromptDone 工作台，先完成数据导入、固定数据跑测、版本留痕、规则/人工评价、同批对比和问题导出，再依据真实使用反馈扩展。

## 二、需求价值

**目标：** 研发和运营能在同一工作台内回答“这次改了什么、对同一批数据是否变好、哪些记录退化、花了多少时间和费用”，并把坏例交给外部工具继续分析。

- **减少重复准备：** 多个具名数据集各自版本化，多个任务选择明确版本，避免每次试跑重新清洗文件。通过实际导入和重复跑测路径验证；准备时间基线待真实使用采集，不预设提升比例。
- **保留可追溯依据：** 任意运行都能追溯输入、节点顺序、Prompt、模型参数、实际消息和输出。修改草稿、增加步骤或切换数据不改写历史。
- **发现退化：** 对齐相同记录，分别看规则、标准答案和人工评价；不把格式正确等同业务准确，不用单个总分掩盖局部问题。
- **支持快速迭代：** 前后端独立开发和发布，工作台内任务目录常驻，多个任务和历史在同一框架内切换；选定坏例可直接复制/下载交给 Codex、Antigravity。

## 三、需求详情

### 3.1 首版边界与操作闭环

首版为本地/内网单实例、单默认工作区，内部人员共享访问口令。采用用户选定的 **A 方案：资产导航**，仅迭代 A。Dataset 与 Workflow 都是工作区下的独立对象，数据不归某个工作流所有；支持多个 Dataset、多个 Workflow 和每个 Workflow 的多次运行，不引入独立任务列表页面。

数据准备路径为：进入数据集 → 导入/清洗 → 发布独立数据版本。它不要求先创建工作流，也不自动绑定最近编辑的工作流。

调优路径为：工作台内选择或新建工作流 → 引用已有数据版本 → 配置线性步骤和 Prompt → 单条验证 → 固定记录批量跑测 → 标注和比较 → 导出报告/坏例 → 修改草稿再验证。同一个数据版本可以被两个或更多工作流引用，不重复导入或复制记录。

- 导入 .xlsx、CSV、JSON，单文件不超过 **20 MB**，单次导入的非空候选记录数 **少于 50,000**。20 MB 按 20,000,000 字节校验；49,999 条在范围内，50,000 条超限。此为单次导入容量，不是系统累计记录量或同时模型请求数。
- 支持单条、前 N 条、随机 N 条；N 等于可用总数即可全量。随机后保存实际 ID 清单，换版沿用清单。
- “多轮”首先指修改 Prompt 后重复跑相同数据。每个 Node 首版只做单轮模型调用，完整记录其发送消息与响应。
- 支持线性多步骤、末尾添加步骤、从基准运行复用成功上游。首版没有分支画布、循环或动态用户模拟。
- 自动评价只包含 JSON 格式、必填字段、可选标准答案严格匹配；人工标记好/坏/未评价与原因。
- 业务翻译作为普通步骤；辅助阅读为逐条点译，费用单列。
- 导出 Markdown 报告、CSV/JSON 明细和 Markdown Context Bundle。平台内 AI 裁判、专用 Prompt Review、AI 聚类/自动改写及自动控制外部 Harness 后置。
- 首版不建设复杂账号权限、跨数据集合并、追加覆盖旧版本、完整翻译管理系统、PDF/匿名分享或生产流量网关。

### 3.2 页面：共享口令入口

未建立有效访问会话时展示，验证通过后进入统一工作台。它是访问入口，不是个人账号系统。

#### 主体板块：进入工作区

##### 口令与会话

**内容说明**

- **共享口令：** 掩码输入，允许粘贴；来源为部署配置，页面不显示已保存口令。
- **进入按钮：** 未输入时禁用，提交时显示校验中，防止重复提交。
- **错误反馈：** 校验失败显示“口令不正确”；网络失败与口令错误区分，保留输入供重试。
- **退出入口：** 位于全局设置/访问区域，退出只结束会话，不取消已触发的运行。

**交互样式**

- **提交口令：** 成功后进入工作台；失败停留本页并显示原因。
- **会话过期：** 引导重新进入；后台运行继续，重新进入后可查询。

**数据处理**

- **input：** 部署端口令配置、用户输入和服务端会话。
- **process：** 服务端验证，使用同源 HttpOnly 会话 Cookie 保护 API 与下载；口令按不可逆校验值处理。
- **output：** 有效会话或错误信息，不创建个人账号/角色。

### 3.3 A 方案：资产导航与工作台

左侧一级导航固定为“数据集／工作台／版本对比”，模型与访问从配置入口进入。数据集是独立资产页，展示全工作区数据，不携带当前工作流的编辑面板或隐式绑定操作。

进入工作台后，任务目录与编辑主体在同一页面，选择工作流原位更新主体，不另拆任务列表页。运行历史保留在所选工作流内；版本对比可从一级导航或当前工作流进入，始终明确比较所属的工作流。工作台与数据页切换时保留草稿和所选上下文，但数据页的操作不依赖当前选中工作流。

#### 3.3.1 左侧板块：多个调优任务

##### 任务目录与新建

**内容说明**

- **任务记录：** 名称、当前数据集及版本、步骤数、运行历史数、最近运行状态。无运行显示“尚未运行”，不生成质量分数。
- **任务查找：** 按名称查询，清空后恢复目录；无匹配显示空状态，不改变正在编辑的任务。
- **新建任务：** 名称不能为空；创建后加入工作台目录并选中，初始一个可编辑步骤、无数据引用、无运行历史。不得继承最近编辑工作流的数据；随后通过选择器引用数据版本。若搜索会隐藏新任务，清空目录搜索。
- **选中状态：** 用底色和明确选中标识区分，不能只依赖微弱颜色。

**交互样式**

- **选择任务：** 更新主体，保留各任务的草稿、当前步骤、选中历史和比较对象。
- **新建任务：** 不进入另一个列表页；取消弹窗不创建。
- **切换任务：** 不取消该任务正在执行的运行；侧栏继续展示运行状态。

**数据处理**

- **input：** 当前工作区 Workflows、各自数据绑定、Node 数及运行摘要。
- **process：** 查询、编辑缓存、历史和标注按 workflow_id 隔离；列表搜索不修改资产。
- **output：** 工作台内常驻任务目录、当前任务上下文或新的独立 Workflow；无数据引用时可编辑配置，不能启动运行。

#### 3.3.2 主体顶部：当前任务与数据引用

##### 任务上下文

**内容说明**

- **任务信息：** 名称、线性步骤数、运行次数、当前 Dataset Version。
- **选择数据集/版本：** 弹窗列出独立 Dataset 和各自版本，明确记录数；每个任务当前引用一份版本，同一版本允许被多个工作流引用。引用只保存版本关联，不复制或取得数据所有权。
- **引用状态：** 显示数据集名称、明确版本、记录数及同版本的引用工作流数量。未选择时显示“尚未选择数据”，运行禁用。
- **主体 Tab：** 调优、运行历史、版本对比，均位于当前任务内。
- **查看数据资产：** 进入独立数据页并定位所引用的版本；工作台目录/编辑面板不混入数据页，返回后恢复工作流上下文。

**交互样式**

- **更换数据引用：** 只修改当前任务后续运行的数据选择，清空不再适用的抽样/复用选择；其他工作流和历史运行仍引用原版本。
- **切换 Tab：** 不自动调用模型、发布版本或覆盖编辑内容。
- **选择历史运行：** 不把历史配置自动写回当前草稿；展示“结果来自历史快照，编辑区仍是当前草稿”。

**数据处理**

- **input：** Workflow 当前配置、Datasets/Versions 和选中的历史 Run。
- **process：** 区分当前编辑态与历史快照；引用变化后重新检查输入映射，不修改 Dataset 或其他 Workflow。
- **output：** 当前数据引用、Tab、步骤和历史选择；无数据时提示先引用已有版本；没有可选数据时引导进入独立数据页导入。

#### 3.3.3 调优 Tab 顶部：线性步骤

##### 添加和选择步骤

**内容说明**

- **步骤条：** 展示顺序、名称、草稿/发布版本状态；当前步骤明显选中。
- **添加步骤：** 在末尾追加，名称必填，生成不因数量变化而重写的 Node ID 和 step_key，默认输入来自前一步输出。
- **输入映射：** 可选 Dataset Record 字段或前序输出；支持整段输出和 JSON 字段。仅允许向前引用。
- **历史缺失状态：** 当前新步骤不在所选旧 Run 中时显示“此运行不包含当前步骤”，不填入其他步骤结果。

**交互样式**

- **添加第 3/4 步：** 更新当前 Workflow 编辑配置，不向旧 Run 补写节点。
- **选择步骤：** 编辑其自己的 Prompt/参数，结果区切换到该 Node 在选中 Run 中的记录。
- **查看旧 Run 最后步骤：** 仅切换查看目标，不删除当前新增步骤。

**数据处理**

- **input：** 当前 Node 序列、稳定标识、映射和所选 Run 节点快照。
- **process：** 检查引用存在、方向及变量；新增仅影响后续 Run。
- **output：** 当前线性 Workflow 或选中 Node；不创建 DAG 画布/循环能力。

#### 3.3.4 调优 Tab 左侧：Prompt 与模型

##### 草稿、发布版本与输入变量

**内容说明**

- **Prompt 编辑：** 支持单轮 System/User 消息模板；保存草稿与发布版本分开。
- **变量：** 使用受控变量路径，例如 raw 绑定 Input.raw，previous 绑定 step_1.output，模板可写 {{raw}}、{{previous.name}}。只读取已声明变量，不执行模板代码。
- **模型：** LiteLLM 模型别名、可选 temperature、输出 Token 上限等适用参数；不支持的参数明确报错，不静默丢弃。
- **输出：** 文本或 JSON；JSON 可配置必填字段。标准答案按 Node 显式绑定，新增步骤默认不绑定，避免错误套用前一步标准答案。
- **版本历史：** 展示编号、Prompt 内容、模型/输出要求快照；“复制为草稿”不改写已发布版本。
- **编辑状态：** 已保存/有修改/保存中/保存失败紧随编辑区，保存失败保留输入。

**交互样式**

- **保存草稿：** 持久化可变编辑资产，不创建版本号、不调用模型。
- **发布版本：** 校验后生成不可变 v1、v2……。
- **复制旧版本：** 写入当前草稿，既有历史保持不变。
- **直接试跑草稿：** 不要求先发布；该次 Run 自动保存实际编辑内容和配置。
- **切换任务：** 当前未保存编辑暂存在各任务前端状态中；保存状态清楚可辨。刷新/离开前对未保存内容给出浏览器提示，已保存草稿和运行快照不丢失。

**数据处理**

- **input：** 当前 Node 的 Prompt Draft、Prompt Versions、输入映射及网关模型配置。
- **process：** 校验变量/字段，区分未提交编辑、已保存草稿、发布版本与 Run 快照。默认每个任务/步骤独立维护草稿，不共享可变草稿引用。
- **output：** 更新草稿、新版本或用于 Run 创建的配置快照；并发保存使用 revision 检查，冲突不静默覆盖另一份编辑。

#### 3.3.5 调优 Tab 左下：跑测控制

##### 记录选择、基准复用与运行控制

**内容说明**

- **单条：** 选择已有 Dataset Record；默认当前选中记录，无选择时取第一条。
- **前 N 条：** 按该数据版本的原始稳定顺序选择，不随界面排序变化。
- **随机 N 条：** 不重复抽取；保存实际记录 ID 与顺序。N 为正整数且不超过可用数量。
- **沿用记录清单：** 从已存在 Run 取相同 ID，不隐式重新抽样；必须同数据版本。
- **基准复用：** 指定基准 Run 与从第 K 步开始；显示实际复用/重跑范围。
- **运行状态：** 显示已完成、失败、跳过、未完成数量；提交中禁用重复启动。
- **取消/重跑：** 取消阻止后续调用；重跑失败或未完成项创建新 Run，原 Run 不覆写。

**交互样式**

- **启动运行：** 冻结数据版本、实际记录清单、节点顺序、输入映射、Prompt、模型参数和输出/规则要求。
- **编辑运行中草稿：** 只影响下一次运行。
- **复用成功上游：** 数据版本/记录一致，上游平台侧配置一致且结果成功、满足下游输入才复用；不满足则重新执行该记录上游。首版不做自动全局缓存。
- **刷新/切任务：** 不取消后台任务；页面重新查询已持久化状态。
- **服务中断：** 保留已完成结果并标记中断，不自动重放可能已执行的模型调用。

**数据处理**

- **input：** 当前配置、版本记录、模式/N/固定清单、基准 Run。
- **process：** 运行前静态校验；为重复提交使用同一 client_request_id 返回同一 Run，手动新跑使用新标识。按有界并发执行，逐 Node 保存完成结果。
- **output：** 新 Workflow Run、记录/Node 执行详情、进度与终态。导入五万条以内不意味着同时发起等量请求。

##### 失败传播

局部超时、JSON 解析失败、必需字段缺失、模型拒绝或输出截断，记录该 Node 的原始响应/原因并使其下游跳过，其他记录继续。鉴权、模型别名或参数配置等批次共有错误停止后续调度，显示修正入口。

- **input：** 网关状态码、响应形状、终止原因和输出校验结果。
- **process：** 区分调用失败、业务格式失败、下游跳过与未执行；未确认的远端调用费用保留未知，不默认为零。
- **output：** 可筛选失败项和新批次重跑入口；不把跳过记录当作模型成功输出。

#### 3.3.6 调优 Tab 右侧：结果、评价和消息留痕

##### 结果表与逐条详情

**内容说明**

- **最近运行：** 默认展示最近几批摘要，并提供当前任务全部历史入口。
- **记录表：** ID、输入摘要、执行/复用状态、规则、标准答案匹配、人工评价、耗时、Token、费用；长内容在详情展开。
- **详情：** 原始 Input、映射后的实际 Node 输入、完整渲染消息、原始响应、解析结果、错误、终止原因、请求模型别名及返回模型/调用标识（若有）。
- **人工评价：** 好/坏/未评价、原因/批注，与规则分开；不允许直接改写模型原输出来提高得分。
- **空与未知：** 未执行、无输出、未检查、无标准答案、未评价、未知用量分别展示。

**交互样式**

- **选中记录：** 展示同一 Run/Node/Record 的详情。
- **标注并保存原因：** 独立更新 Trace Annotation，不覆盖自动检查。
- **筛选坏例：** 可按人工坏、规则失败、执行失败查看；选择范围明确，筛选变化清空不再可见的批量选择。
- **复制/导出：** 支持原文复制、CSV/JSON 明细和选中记录 Context Bundle。

**数据处理**

- **input：** 所选 Run 的 Execution Traces、对应输入版本、规则结果和 Trace Annotations。
- **process：** 按 Run/Node/Record 稳定标识关联；统计实际覆盖，复用有来源引用；历史没有当前 Node 时显示缺失状态。
- **output：** 当前结果、人工标注和导出内容；历史实际输入输出保持只读。

##### 分项指标与统计口径

- **规则通过率：** 当前 Node 通过全部已配置适用规则的记录数 / 实际完成规则检查数。JSON 解析失败属于格式检查失败，不从分母隐藏；没有适用规则、没有可检查响应或未执行时单列。
- **必填字段初始语义：** 检查键存在，不把 0、false 或空字符串一律当成缺失；业务非空要求不凭空推断。JSON 无法解析时整体规则失败。
- **答案匹配率：** 严格匹配数 / 有标准答案且实际完成比对数。文本不自动忽略空白/大小写；JSON 比较结构和值，忽略对象键顺序、保留数组顺序、不隐式转换类型。
- **人工好评率：** 好 /（好＋坏），未评价不进入分母；同时展示已评/总数和好/坏数量。
- **零分母：** 显示暂无数据/不适用，不显示 0% 或 100%。
- **执行覆盖：** 总选中数及成功、失败、跳过、未完成分别显示，避免只看通过率隐藏执行问题。
- **耗时：** 整批实际开始到结束的墙钟耗时，排队等待单列；单条/Node 显示其执行耗时。并发下不能以各步骤耗时简单求和冒充整批耗时。
- **Token/费用：** 输入输出用量按真实 usage；缺失显示未知。已知费用可显示小计，并注明未知数量。真实业务调用和辅助翻译分列，复用来源费用不重复计入本次。

这些指标不合成为一个总分；没有业务标准答案时不能把 JSON 通过率称为业务准确率。

### 3.4 当前任务主体：运行历史与版本对比

#### 3.4.1 运行历史 Tab

##### 多批次历史表格

**内容说明**

- 列为批次编号/时间、数据集与版本、步骤及 Prompt 版本、模型、记录数、状态、A/B 操作；完整参数可展开。
- 完成但含错误时显示失败/跳过数量，与全部成功区分。
- 根据批次、数据、模型、状态查询，按创建时间倒序分页；仅包含当前任务。
- 运行快照与当前编辑配置不同则明确说明，尤其是已添加新步骤或切换数据时。

**交互样式**

- **选择历史：** 显示该批次冻结结果，保持当前编辑草稿。
- **设为 A/B：** 在历史表直接选两次运行，进入同任务对比。
- **新增步骤后看旧历史：** 不补写节点，提示该步骤当时不存在。

**数据处理**

- **input：** 当前 workflow_id 下的 Runs 及节点/数据/模型快照。
- **process：** 按历史快照填充列；搜索/分页不改变结果或当前数据绑定。
- **output：** 可追溯历史、选中 Run、比较对象；不同任务的历史不混合。

#### 3.4.2 版本对比 Tab

##### 配置 Diff、输出 Diff 与变化摘要

**内容说明**

- 必须是同任务、同 Dataset Version、相同记录清单、两个运行共有的同一 Node。新增步骤在任一历史中不存在时不可直接比较。
- 同屏展示 Prompt/模型参数/输出要求差异、分项指标与覆盖、逐条原始输出。
- 退化置顶：规则通过→失败、答案匹配→不匹配、人工好→坏分别标记；执行成功→失败/跳过另标执行退化。
- 任一侧未评价不能伪造人工好坏变化。不同规则口径需统一重评或明确标注不可直接比较。
- Prompt 与模型/拓扑一起变化时提示多项条件变化，不把整体耗时/费用变化归因于单一 Prompt。

**交互样式**

- **切换 A/B：** 校验对齐条件，条件不满足时提示原因和重新选取/跑测入口。
- **查看退化记录：** 按 ID 展示同一输入 A/B 输出及标注。
- **下载报告：** Markdown 汇总与 CSV/JSON 明细，包含生成时间及口径；摘要由统计和 Diff 确定性生成。

**数据处理**

- **input：** A/B 配置快照、记录 ID、规则和人工结果、实际消耗。
- **process：** 稳定 ID 配对，计算分项变化、覆盖和退化；缺失、未完成、未评价单列。
- **output：** 配置/输出 Diff、变化摘要、报告和选定坏例。报告中本 Node 指标与整个 Workflow 消耗明确分开。

### 3.5 独立数据页：多个数据集、引用关系与导入清洗

从 A 方案左侧“数据集”入口进入，不要求先选择或创建工作流。该页不展示任务目录或“用于当前任务”按钮；查看、导入、清洗和发布都是独立数据资产操作。

#### 3.5.1 数据集列表与版本预览

##### 多数据集目录

**内容说明**

- 列表为名称、版本数量、最新记录数、引用工作流及操作；支持按数据集名称查找，查询只筛选列表，不改变预览版本或任何工作流引用。
- 引用关系展示工作流名称与其当前引用版本，允许同一数据集/同一版本出现两个或更多工作流。未被引用的数据集仍可独立保存，显示“未被引用”。引用数按当前工作流配置计数，历史 Run 的使用不混入当前引用数。
- 选择 Dataset 后预览其某个版本；列表“最新记录数”与正在预览的旧版记录数分开。
- 支持新建 Dataset、向指定 Dataset 重新导入生成新版本、只读预览、查看引用工作流及“在工作流中使用”。
- 预览展示记录 ID、Input、可选 Expected Output、原始位置与清洗状态；分页读取。

**交互样式**

- **新建数据集：** 名称非空，导入后产生首个版本。
- **新增版本：** 保留旧版，只生成后续版本；所有工作流继续使用原来显式选择的版本，不自动升级。
- **在工作流中使用：** 打开引用弹窗，先显示当前数据集/版本，再明确选择一个目标工作流；默认不选目标，不根据最近编辑对象隐式绑定。显示目标原引用与新引用，确认后只修改该工作流后续运行。已有其他引用和旧 Run 不变。
- **查看引用工作流：** 进入相应工作流编辑区，不改变数据引用。
- **只读预览：** 不自动改变任何工作流绑定。

**数据处理**

- **input：** 工作区 Dataset、Versions、Records 及引用它们的 Workflows；引用弹窗的目标来自工作区工作流目录，与当前工作台选中项无隐式关联。
- **process：** 版本与记录稳定关联，同版本被多个工作流引用时共享同一份只读记录。只有明确确认引用时才更新目标 Workflow；Input 字段变化须在运行前重新校验映射。
- **output：** 数据目录/预览、独立新版本、引用关系或明确目标的配置更新；首版不提供跨数据集 join、原版本追加覆盖或独立 ETL 平台。

#### 3.5.2 导入弹窗：选择文件、映射、清洗确认

##### 文件解析与角色映射

**内容说明**

- 支持 .xlsx、UTF-8/UTF-8-BOM CSV、JSON 对象或对象数组。其他格式/编码显示明确错误，允许用户整理后重导，不静默乱码转换。
- Excel 每次选择一个 Sheet，默认首个非空 Sheet，首行作为表头；CSV 首行表头，按 CSV 解析记录而非物理行数计数。
- JSON 单个对象是一条记录；对象数组的元素各一条。复杂嵌套数组路径抽取后置，不自动拆分任意嵌套对象。
- 映射一个或多个字段为 Input 变量，可选 Expected Output；未映射字段不参与模型输入，原文件保留供追溯。
- Input 键名不能为空或重复。源文件空表头/重复表头需用户在预览中修正映射或改文件，不能静默覆盖同名列。
- 缺失、null、空字符串、0、false 区分保存。Expected Output 保留是否提供标识；Excel/CSV 空单元格默认无答案，JSON 显式值按字段存在性处理，不因值为 false/0 被丢弃。

**交互样式**

- **选文件/Sheet/映射：** 更新采样预览并显示处理进度；采样成功不等于全量已通过。
- **超限：** 文件大于 20 MB 或候选记录达到 50,000 条则停止，不静默截取前几条当全量。
- **空文件/无可用记录：** 显示原因并禁止发布空数据版本。

**数据处理**

- **input：** 上传文件、Sheet、字段角色和列类型。
- **process：** 文件先保存原件，服务端解析、计数、分段写草稿；上限在排除错误记录前校验。表头和全空记录不计候选记录；非空但内容错误的记录计入容量。
- **output：** Import Draft、预览、原始位置和错误统计，尚未发布 Dataset Version。

##### 显式 JSON 清洗与发布

**内容说明**

- 普通文本列不自动按 JSON 修复。用户指定 JSON 类型后才进入清洗。
- 标记直接通过、格式修复、失败、排除，展示修复前后文本和失败原因。
- 不猜缺失字段/值，不补造截断内容，不使用 eval 执行文件文本。
- 失败记录可筛选、排除、导出原文与位置/错误原因；首版可在外部修正文件后重新导入。
- 发布前显示总候选、通过、修复、失败、排除、最终纳入数；仍有未处理失败记录时禁用发布。

**交互样式**

- **确认清洗预览：** 用户检查自动修复候选，不把修复当作业务准确性证明。
- **排除错误并导出：** 排除选择明确；保留原始信息供修补。
- **保存版本：** 整批草稿校验后原子发布新版本；部分解析失败或进程中断不产生冒充完整的新版本。
- **取消：** 不发布；临时文件/草稿与已发布原件生命周期分开。

**数据处理**

- **input：** 显式 JSON 列、原文和解析草稿。
- **process：** 优先严格 JSON；失败后可去除完整代码围栏等已知包装，再使用不补内容的语法容错候选，最后重新严格序列化/校验。重复键、非有限数、缺值和未闭合结构判失败。语法合法不保证业务完整，业务语义仍由标准答案或人工判断。
- **output：** 带清洗留痕的不可变 Dataset Version、稳定 record_id、Input/Expected Output/原始位置及原件引用。

导入清洗与模型输出检查是不同链路：模型输出仍按声明的格式严格检查，不能用容错修复把实际失败隐藏为成功后继续下游。

### 3.6 通用模块：翻译、设置与导出

#### 3.6.1 翻译接入

**内容说明**

- 业务翻译作为普通 Node，输入原文/目标语言等变量，输出供后序步骤使用，按业务调用统计。
- 辅助阅读为单条“译成中文”，展示在原文旁或下方，不覆盖原输出、不改变原检查结果。
- 辅助译文、所用模型与费用单独关联；不默认整批翻译，不建设术语库/多语种矩阵。

**交互样式**

- **逐条点译：** 发起明确的辅助调用，显示加载/失败/译文；原文始终保留。
- **选择翻译模型：** 使用独立 LiteLLM 别名，既有译文保留其来源配置。

**数据处理**

- **input：** 指定 Run/Node/Record 的原始输出及辅助翻译配置。
- **process：** 作为独立辅助请求记录，不写回业务输出或自动评价。
- **output：** 译文记录、usage/费用及来源，费用在报告单列。

#### 3.6.2 LiteLLM 与访问设置

**内容说明**

- 配置 LiteLLM Base URL、网关访问密钥、运行/翻译模型别名及可选单价。
- 网关由本项目部署，上游厂商凭证和模型路由在 LiteLLM 管理。平台使用网关应用凭证，不需要在工作台重复维护厂商原生 API。
- 密钥只显示掩码，留空保持原密钥，显式输入才替换；服务端加密保存，日志和下载不输出明文。
- 模型别名可以指向不同部署；Run 记录请求别名和网关实际返回标识（若有），不宣称冻结了外部模型或网关内部路由。
- 连通性/模型支持情况必须针对实际网关验证，不能根据名称推断某模型支持所有参数。

**交互样式**

- **保存设置：** 先校验地址和配置，成功后更新后续可选模型；取消不覆盖。
- **测试连接：** 显示实际认证/服务状态；需要模型探测时明确其为一次小请求，不把成功连接等同质量达标。

**数据处理**

- **input：** 服务端配置、网关允许的模型别名和用户输入。
- **process：** 校验、加密、掩码、保存配置版本；历史参数/单价快照不改写。
- **output：** 后续模型调用配置、连接反馈，不把网关管理凭证发送浏览器。

#### 3.6.3 报告、明细与 Context Bundle

**内容说明**

- Markdown 报告包含任务/数据/Run/Node、配置变化、统计口径与覆盖、退化摘要、耗时/Token/费用和未知项。
- CSV/JSON 明细包含稳定 ID、输入、预期/实际输出、执行状态、规则结果、人工评价/批注和消耗；CSV 进行规范转义以便 Excel 打开。
- Context Bundle 由用户选择记录后预览，包含实际 Prompt、模型参数、输入、预期/实际、错误和批注；对比场景包含 A/B 对照，复用结果保留来源。
- 只构建允许的业务字段，不直接序列化环境变量、Model Provider 密文/密钥或 Authorization。

**交互样式**

- **复制文本：** 实际复制成功才提示成功；权限受限时保留可选择文本。
- **下载：** 导出当前选择与生成时的口径/标注快照；失败不误报成功。
- **交接外部工具：** 用户自行复制/下载给 Codex、Antigravity。建议手动贴回 Draft，再沿用相同记录验证。

**数据处理**

- **input：** 所选 Run/Node/记录、配置快照、评价与批注。
- **process：** 按生成时一致快照汇总、过滤凭证、规范序列化，大明细服务端分段生成。
- **output：** 可复制 Markdown 或下载报告/明细，不自动发送、不自动修改业务代码。

### 3.7 后台模块：技术选型与部署

#### 四服务、前后端独立迭代

- **web：** React＋TypeScript＋Vite，基础组件使用 Tailwind CSS/shadcn 风格，查询与表格可用 TanStack Query/Table；列表服务端分页。生产由前端容器托管构建产物和 /api 反向代理。
- **api：** Python FastAPI＋Pydantic，SQLAlchemy/Alembic 管理平台数据库；HTTPX 异步客户端通过 HTTP 调用 LiteLLM，不在业务进程嵌入 LiteLLM SDK 充当网关。[HTTPX 异步调用依据](https://www.python-httpx.org/async/)
- **litellm：** 独立 LiteLLM API 服务，项目内一并部署，显式单 worker；配置模型别名、厂商凭证、限流/重试及成本信息。[官方部署边界](https://docs.litellm.ai/docs/proxy/docker_quick_start)
- **postgres：** 一个实例内分 promptdone、litellm 两个逻辑数据库，独立用户/迁移；业务用 JSONB 保存动态输入和快照。原件/留存导出用本地卷。

开发时 apps/web 和 apps/api 独立启动，Vite HMR 与 FastAPI reload 分离，OpenAPI 生成 TypeScript 契约；前端更新不重启跑测 API，后端重载仍受进程内任务中断边界约束。部署配置放 infra，LiteLLM 配置不提交真实凭证。依据见 [Vite 代理](https://vite.dev/config/server-options)、[FastAPI CLI](https://fastapi.tiangolo.com/fastapi-cli/)。

首版不增加独立 Worker、Redis 或 Token SSE；页面轮询持久态。LiteLLM 单 worker 的基本转发不强制 Redis，多 worker/副本或特定缓存需求需另行评估。[Redis 条件](https://docs.litellm.ai/docs/proxy/redis_requirements)

#### 文件解析组件（实现建议 D01）

- CSV 使用 Python csv，按解析记录计数，保留字符串，严格报告坏格式；单字段大小限制与文件上限协调，不因标准库默认小字段限制误拒长文本。[官方依据](https://docs.python.org/3/library/csv.html)
- XLSX 使用 openpyxl read_only 流式读取，读取结束关闭文件，不只相信工作表维度元信息计数。[官方依据](https://openpyxl.readthedocs.io/en/stable/optimized.html)
- JSON 先用标准 json 解析，并显式拒绝重复键及非有限数，不能仅依赖标准库默认行为。容错候选可使用包名 json5（dpranke/pyjson5），处理单引号/尾逗号等语法变体，同样禁用重复键、拒绝非有限数和未消费的尾部内容。它不是自动补全缺值的算法；实际支持的变体须形成测试样例，不能宣称只支持某两类却无意开启全部语法。[JSON 依据](https://docs.python.org/3/library/json.html)、[JSON5 依据](https://github.com/dpranke/pyjson5)
- 解析/清洗进入有界后台线程/任务，避免阻塞 API 事件循环；分段写入草稿。前端采样预览不能代替全量校验。

#### 后台运行边界

- 平台仅单 API 实例/worker，使用有界并发与持久状态管理运行。浏览器请求结束不等于任务结束，刷新不取消。
- 导入/运行状态先落库，后调度；启动时将遗留未完成任务识别为 interrupted，不自动重放付费调用。
- 每个完成 Node 的原始结果和状态提交后再向下游传递，数据库故障不能继续制造无日志的调用链。
- 平台和 LiteLLM 统一设置超时/重试预算；平台默认不透明重试，避免与网关叠加；人工重跑另建批次。
- **建议初值 D02：** 模型全局并发 3、页面轮询 2 秒、列表每页 20、导入分段写入 500 条。均为可配置工程初值，不是实测吞吐保证或新业务容量限制；实际模型配额和典型数据需验收。

**input：** 请求、配置快照、文件与数据库持久态。

**process：** 单实例有界调度、短事务写入、校验与调用预算；区分运行/取消/中断/局部失败。

**output：** 持久状态、进度、原始证据与明确终态；没有真实环境验证前不承诺处理耗时或每秒吞吐。

### 3.8 后台模块：核心数据与接口契约

#### 数据关系与不变项

- **Dataset → Dataset Version → Dataset Record：** 工作区下独立资产、不可变数据版本、标准化输入记录，不属于某一个 Workflow。记录保留 source_index、Input、标准答案及是否提供标识、清洗状态、原始位置/原件引用。
- **Import Draft：** 发布前可变的解析/映射/清洗暂存，支持逐记录状态；不能让五万条原文都堆进一个浏览器对象。
- **Workflow → Node：** 当前任务与线性配置，Node 使用稳定 ID/key。步骤默认拥有独立 Prompt Draft/Versions，避免跨任务共享草稿造成误改。
- **Workflow → Dataset Version：** 当前可为空的版本引用，启动运行前必选；一个版本可被多个 Workflow 引用，禁止为每个工作流复制整份 Dataset。新建数据/工作流互不强制创建对方；修改数据版本引用不联动其他工作流。
- **Workflow Run：** 绑定 workflow_id、dataset_version_id、实际 ID 清单和完整 Node/Prompt/模型/参数/规则快照；创建后不覆盖配置。状态与完成证据追加保存。
- **Execution Trace / Node 执行：** 按 run、record、node 记录输入、渲染消息、响应、解析、错误、终止原因、时延、usage、费用与复用来源。
- **Evaluation Run：** 保留检查配置和自动结果快照；历史按统一口径重评时产生新的评分记录，不覆盖旧口径。
- **Trace Annotation：** 对具体执行的人工评价与批注，独立可编辑。报告捕获其生成时状态。
- **辅助翻译：** 单独记录源输出、译文、模型与消耗，不混成业务 Node 输出。
- **Model Provider/网关配置：** 地址、别名配置、加密访问密钥、单价及版本；输出安全字段。

引用过的数据版本、Prompt 版本和 Run 不允许被新导入/发布/新增步骤原地替换。当前 MVP 不提供物理删除历史链路的业务按钮。普通编辑字段可变与不可变快照需在接口层分开。

#### REST 契约范围

统一 /api/v1，响应和错误由 Pydantic/OpenAPI 定义，生成前端类型；列表支持分页，错误含 code、message、details，不返回服务端凭证。

- /auth/session：口令建立/检查/退出会话。
- /datasets、/datasets/{id}/versions：独立目录、版本、分页记录及引用工作流摘要，不嵌套在某个 Workflow 下。
- /import-drafts：上传、解析/清洗状态、映射、错误导出、发布。
- /workflows、/workflows/{id}/nodes：独立任务、明确数据版本引用、线性 Node 配置和追加；更新引用只作用于指定 workflow_id。
- /prompts/{id}/draft、/prompts/{id}/versions：保存草稿、发布和查看；这些是后台对象，不新增一级资产页面。
- /workflows/{id}/runs、/workflow-runs/{id}：启动、历史、进度、快照、分页记录、取消和重跑。
- /node-executions/{id}/annotation、/node-executions/{id}/translation：人工标注与辅助翻译。
- /comparisons、/exports：按明确 Run/Node/ID 配置对比及生成报告/上下文。
- /model-providers：网关配置、掩码响应与连接反馈。

LiteLLM 调用走网关 Chat Completions HTTP 接口；使用请求模型别名，不把别名当厂商固定版本。usage 和可用费用信息按真实响应留存；x-litellm-response-cost 缺失或因无匹配费率返回零时不能据此断言免费。单价/币种随快照保存，同报告按币种分组不自行换汇。依据见 [客户端接入](https://docs.litellm.ai/docs/proxy/client_setup/overview)、[费用边界](https://docs.litellm.ai/docs/proxy/model_cost_map)。

**input：** 前述模块的业务对象、显式选择和客户端提交标识。

**process：** 验证工作区/父子引用、版本与节点存在性，参数与输入快照一致；约束重复启动和非法历史改写。

**output：** 可追溯且前后端一致的业务记录/API；接口清单是本版拟实现契约，不是已有接口声明。

### 3.9 端到端验收与验证方式

以下为实现验收目标；原型只验证交互演示，尚未完成真实容量、数据库或模型联调。

- **独立数据与复用：** 不创建工作流即可导入 D1、D2 并保存版本。工作流 A、B 同时引用 D1 v1，使用相同数据/记录标识，不复制数据，Prompt/步骤/历史各自独立。数据页能看到两个引用及其版本。
- **引用隔离：** 发布 D1 v2 后 A/B 仍为 v1；只将 A 改为 v2，B 和所有旧 Run 仍为 v1。数据页引用操作必须明确选目标；单纯预览不改引用。旧版预览记录数与最新计数可区分。
- **新工作流：** 无论从哪个工作流开始创建，初始无数据引用，未选数据不能运行；选择已有 D1 v1 后不新增数据副本。
- **容量边界：** 文件恰为 20,000,000 字节与 49,999 条候选记录在格式有效时允许处理；多 1 字节或达到 50,000 条明确拒绝，不截断冒充成功。CSV 跨行内容按解析记录计数。
- **偏 JSON：** 指定 JSON 列可对可解释格式问题产生修复候选，原文留存；普通文本不变。截断/缺值/重复键/非有限数不补造；排除失败并导出后发布，未处理失败和空数据不能发布。
- **任务隔离：** 两任务各自保存草稿和历史，切换不丢编辑状态，不混用模型/数据/运行；当前 Run 与当前编辑区可明确区分。
- **追加步骤：** 两步任务已有 Run A，追加第 3/4 步，A 仍只有两步；新 Run B 包含四步。查看 A 的新步骤显示不存在，不复制其他步骤结果。
- **A 方案与多历史：** 一级资产导航为数据集、工作台、版本对比；独立数据页不带当前工作流面板。工作台目录与编辑主体同页，至少多于一页的历史可分页/筛选；从表格设 A/B 进入对比，不经过独立任务列表。
- **同批验证：** 随机抽 N 条后保存清单，换版沿用完全相同 ID。Prompt/模型参数变化有 Diff，能看到平均指标不变时的个别退化。
- **上游复用：** 相同输入和上游配置、成功结果时可复用；变数据/映射/Prompt/模型参数或上游失败时不误用。来源可追溯，费用不重复计算。
- **失败与恢复：** 局部错误只跳过该记录下游，共有鉴权错误停止后续。取消保留完成项，刷新/切任务不取消；API 重启后识别中断，手动重跑形成新批次。
- **评价口径：** 10 条里人工评 4 条、3 好 1 坏时为 75%、覆盖 4/10，未评不算坏；无标准答案不制造准确率；无 usage/价格不显示真实零费用。
- **翻译与导出：** 辅助中文不改变原文和原评分，费用单列；CSV/JSON 和 Markdown 内容与生成时口径一致，选中坏例可复制/下载且无系统凭证。
- **独立迭代与部署：** 前端更新不重启 API；四服务可按依赖启动，应用与网关迁移各自数据库；服务/持久卷重启后已保存资产仍在。

实现测试使用真实测试 PostgreSQL 与可编程 LiteLLM HTTP 替身，覆盖错误、超时、缺 usage、部分失败和重复启动；再以少量真实网关调用核对参数/响应兼容性。浏览器端验证独立数据页、同版本多工作流引用、工作台内任务目录、步骤追加及历史/对比/导出主路径。模型输出提升没有基线时不编造达成比例。

### 3.10 后续迭代顺序与资料追溯

- **使用反馈优先：** 实际文件解析变体、常用规则、错误类型与操作耗时先记录，再决定补充导入规则、在线修补或批量操作。
- **第二阶段：** 高阶 Prompt Review、可校准的 AI 裁判、AI 聚类/改写建议、黄金数据回流；每项独立计算成本并验证收益。
- **容量/协作驱动：** 确有多实例、更新 API 不断跑批或恢复要求时引入独立 Worker/Redis；按实际需要增加账号权限或对象存储。
- **复杂流程后置：** 分叉/循环、单记录多轮对话、多语种矩阵和完整本地化资产管理另行决策。
